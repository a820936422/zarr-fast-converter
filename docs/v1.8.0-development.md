# Fast NC Zarr v1.8.0 开发文档

- **目标版本**：v1.8.0
- **基线版本**：v1.7.9（开发中）
- **文档更新**：2026-08-18
- **关联文档**：[维护文档](MAINTENANCE.md)、[模块与运行指南](README.md)

本文档记录 v1.8.0 的后续待处理内容。v1.7.9 已完成的 Python 侧后端优化作为基线，剩余需要架构/Rust 改造或进一步验证的项统一列入 v1.8.0。

---

## 1. v1.7.9 已完成内容（基线）

- 版本提升至 1.7.9。
- 存储感知 worker/batch **初始值**（非硬上限），调优保留全范围 worker 扫描。
- `HardwareProfile`：存储顺序读/写带宽、随机 4K IOPS、NUMA 拓扑、P/E 核识别、缓存。
- `PerformanceModel`：候选耗时估算与排序（`FAST_NC_ZARR_PERF_MODEL=1` 启用）。
- 重分块存储感知初始值 + 全范围实测。
- `WorkerPool` 工具类。
- 文件亲和排序（HDD）。
- `OnlineController`：启发式规则、直写可观测性、保守 pending 主动调整。
- CPU affinity（`FAST_NC_ZARR_CPU_AFFINITY`）。
- PipelineFusion eligibility 标记。
- Python 测试 251 passed。

---

## 2. v1.8.0 目标

1. 把 v1.7.9 中“工具已就绪但未全路径接入”的优化真正接入转换/重采样/重分块执行路径。
2. 实现流水线单遍流式融合，降低中间 Zarr 写放大。
3. 扩展 native 能力，覆盖 int16 / HDF-EOS / 更多重采样方法。
4. 建立真实数据 scaling 基准并纳入发布门禁。

---

## 3. 待办清单

### 3.1 后端性能与调度

- [x] **WorkerPool 全路径接入**
  - `WorkerPool` 已升级为完整后端池原语：支持 `initializer`/`initargs`、`cancel_event`、动态 `pending_limit_fn`、`submit`/`shutdown` 与有序 yield；
  - 已接入 `direct_write`（writer.py）、文件名时间写入与 filename 结构检查（filename_mode.py）、inspection、重分块阶段 1/2 与 worker 调参（rechunking/engine.py）、重采样空间并行（resampling/engine.py）；
  - “worker 初始化依赖输出路径”按调用重置：每个操作用当前输出/staging 路径构造池并在 `finally` 中 `close()`，不会把旧上下文泄漏到后续操作；
  - 池大小沿用各后端已有的 memory-budget 约束（worker 数来自 `plan.workers`/`_parallel_workers`/`space_workers` 等），空闲时 `close()` 释放进程；
  - 新增 `tests/test_adaptive_runtime.py` 覆盖 initializer、serial 路径、取消、submit/shutdown、动态 pending 限制。
- [x] **读写阶段分离（跨设备 staging 基础设施）**
  - `make_staging_path(target, operation, staging_root=None)` 支持把最终 staging 放到 scratch 设备；
  - `publish_staging` 新增跨文件系统发布：先复制到输出设备侧 sibling temp、fsync 后原子 rename（`allow_cross_device=True` 默认开启），远程 staging 随后清理；`allow_cross_device=False` 保留原“必须同文件系统”拒绝语义；
  - `engine.convert` 与 CLI 新增 `--staging-root`；新增发布单元测试（跨设备复制发布、staging-root 路径、转换端到端 staging-root 清理）；
  - 保留原子发布与失败回滚语义。
- [x] **读写阶段分离（可测收益基准）**
  - `benchmark_scaling.py` 新增 `--compare-staging`：每个 worker 同时跑“直接写输出”与“scratch staging + 发布复制”，报告 `staging_comparisons`（吞吐/耗时 delta）；
  - `pixi run scaling-check` smoke 已覆盖该对比路径；
  - `ConversionConfig.staging_root` / pipeline 原始转换阶段 `staging_root=paths.root` / filename 转换已接通跨设备 staging。
- [x] **读写阶段分离（同设备分批调度算法）**
  - filename 时间写入新增 `phase_batch`：同一 WorkerPool 上有界窗口内先读后写（窗口内全部读取完成后才写入），降低同设备 HDD 读/写磁头争用；
  - 内存以窗口大小为界（`max(1, worker_count)` 个任务的原始源数组）；
  - CLI `pixi run convert -- --phase-batch`（filename 模式）；新增 parity 测试（`tests/test_filename_mode.py` 17 passed）。
- [ ] **读写阶段分离（真实设备验证）**
  - 在真实 HDD/SSD 双设备上执行 `benchmark_scaling --compare-staging` 与 `--phase-batch` A/B，记录收益并纳入发布门禁说明。
- [ ] **PipelineFusion 单遍流式执行**
  - 基于 `streaming_fusion_eligible` 标记实现真正的单遍流式；
  - 转换 worker 在内存中按目标 chunk 产出，直接进入重采样/重分块；
  - 保留 staging、原子发布、失败清理与 checkpoint 语义；
  - **已落地证据层**：raw pipeline manifest 新增 `fusion` 块（`eligible`/`stage`/`intermediate_validation_skipped`/`write_amplification`），测试覆盖 fusion-eligible 路径（`tests/test_pipeline.py` 41 passed）。
- [x] **OnlineController 扩展到全部后端**
  - 接入 `run_resample`（`_run_parallel_tiles`）与 `run_rechunk`（阶段 1/2）并行路径；
  - 动态调整 in-flight pending 窗口：`spill_memory`/`reduce_workers` 降低 pending，`increase_batch` 提高 pending（近似批量），`reduce_compression` 记录事件（codec 无法中途改写）；
  - 所有调整以 `online_adjustments` 事件返回，并聚合进 pipeline manifest 顶层 `online_adjustments`（raw 与 zarr pipeline 均覆盖）；
  - worker 数在池创建时固定；实际 worker 调整仍由调参阶段完成（已有 worker_tuning）。
- [x] **PerformanceModel 默认启用与剪枝**
  - 候选排序/剪枝已从 `FAST_NC_ZARR_PERF_MODEL=1` 改为默认启用；`FAST_NC_ZARR_PERF_MODEL=0/off/false` 可关闭（调试用）。
  - 有缓存 HardwareProfile 时按估算耗时排序，短调参预算优先评估更优候选；
  - 剪枝保留全部 1..worker-ceiling worker 扫描候选，仅压缩/布局/batch 候选按估算排序截断；
  - 新增 `keep_full_worker_sweep` 与 `performance_model_enabled` 单测（`tests/test_performance_model.py` 8 passed）。
- [x] **HardwareProfile 调度集成**
  - `storage_initial_workers(profile, ...)`：用实测顺序写带宽动态调整 HDD 初始 worker（≥150 MiB/s 时由 4 提升到 8），已接入 `planner.initial_plan`（有缓存 profile 时优先，并写入 rationale）；
  - `affinity_spec_from_profile(profile)`：由 NUMA/P/E 核生成 CPU affinity spec（性能核覆盖 worker ceiling 时只用 P 核，否则全逻辑核），供 `FAST_NC_ZARR_CPU_AFFINITY` 使用；
  - 新增 `tests/test_hardware.py` 与 `tests/test_performance_model.py` 覆盖。

## 4. 验收标准（v1.8.0 完成定义）

1. WorkerPool 在转换/重采样/重分块/pipeline 中实际复用，短任务与多阶段开销下降。
2. 源/输出同设备 HDD 场景有可测的读写阶段分离收益。
3. Pipeline 在 eligible 路径实现单遍流式，`write_amplification` 下降。
4. OnlineController 在主要后端实际调整 worker/batch/压缩并记录事件。
5. native 至少覆盖 int16 或 HDF-EOS 之一，并通过真实数据 parity。
6. 真实数据 scaling 基准纳入发布门禁。
7. 全量回归保持绿色，文档同步完成。
