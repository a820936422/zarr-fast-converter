# 一条龙模块 V1 实现方案

## 1. 目标、范围与原则

“一条龙”模块面向已经下载到本地的一批同构地理栅格文件。用户描述最终要得到的数据产品，系统完成检查、转换、重采样、重分块和压缩，而不是让用户手动依次运行多个模块。

典型任务：全球 8 日尺度的 GOSIF-GPP TIFF，处理为 2001--2022 年、纬度 30--90°N、经度 -180--180°、0.1° 网格、时间连续 chunks、指定压缩方式的 Zarr v3。

V1 范围：

- 输入为单个同构 NC、HDF 或 TIFF 文件目录；
- 源数据必须可标准化为一维、规则、单调的 `lat/lon`；数据变量必须为数值型；
- 支持时间/空间裁剪、变量变换、空间重采样、最终重分块和无损压缩；
- 支持 GUI 的“一条龙处理”页面，以及等价的 CLI/API；
- 所有阶段支持计划预览、取消、阶段报告和安全清理。

V1 不包含多来源拼接、非规则/曲线网格、投影坐标转换、分类变量的专用重采样、时间聚合（例如 8 日转月）、统计分析，以及“原始文件直接流式写出最终重采样 Zarr”的融合实现。

核心原则：

1. 先完整检查，后创建处理计划，绝不重新猜测已确认的时间规则。
2. 计划器统一决定各阶段的布局和资源；执行器只按计划运行。
3. 需要重采样时，中间 Zarr 为重采样读取服务；只有最终层使用时间连续布局和用户压缩。
4. 临时产物采用低成本编码，成功前不触碰已有最终输出。
5. 若源网格已经与目标完全一致，应跳过不必要的重采样和二次读写。
6. 最终数据产品具有唯一的坐标、维度和排序规范；所有阶段的校验均以该规范为准。

### 1.1 最终 Zarr 规范

最终输出（包括“不需要重采样”的直接输出）必须满足以下不随源文件改变的规范：

| 项目 | 强制规则 |
|---|---|
| 空间/时间维度名 | `time`、`lat`、`lon`。 |
| 三维数据变量维度顺序 | `("time", "lat", "lon")`；V1 不接受带额外数据维度的变量。 |
| 时间坐标 | 归一化为日精度的 `datetime64[ns]`；面向用户显示和序列化为 `YYYY-MM-DD`。 |
| 时间排序 | 严格升序，无重复；补齐时间只能写为缺测切片。 |
| 经度坐标 | 严格升序，即从左（西）到右（东）；全球范围规范为 `[-180, 180]` 的像元中心。 |
| 纬度坐标 | 严格降序，即从北到南。 |
| 缺测语义 | 保留/写入变量的明确填充值或 `NaN`，不得用零表示没有覆盖的数据。 |

源数据的坐标方向不同并不是拒绝理由。转换阶段必须随数据一起重排坐标和数组轴，使中间
和最终 Zarr 均满足上述规范；不得只反转坐标而不反转数据。重采样的目标网格也必须
以经度升序、纬度降序构造。该规则与当前转换模块的输出约定一致，并使不同来源的一条龙
结果可以直接拼接和比较。

## 2. 用户流程

### 2.1 必经的检查与时间规则确认

用户选择源目录后，界面只能先进入现有的数据检查流程。后续参数页面和“执行”按钮在检查完成前保持禁用。

~~~text
选择源目录
  -> 文件时间维度信息检查
  -> 用户确认完整日期 / 年 / DOY 等时间规则
  -> 完整结构、变量、坐标和时间缺口检查
  -> 产生完整 InspectionResult（可保存 schema v2 快照）
  -> 解锁“一条龙处理”
~~~

一条龙任务必须引用本次确认后的 `InspectionResult`（或完整检查快照），不得重新从文件名推断时间字段。执行前比对快照记录的源文件集合、大小和修改时间；发生变化则拒绝运行并要求重新检查。

时间缺口在检查阶段展示。V1 默认阻止任务创建；用户明确选择“按已确认频率补齐为缺测切片”后才能继续。输出仍保留原始频率，例如 8 日；“时间连续”只表示理论时间轴完整且最终 chunks 在 time 维连续，并不将 8 日数据插值为日数据。

### 2.2 四个参数面板

检查通过后，GUI 显示四个面板和只读的“执行计划预览”。填写参数不会创建任何 Zarr；只有“生成计划”通过全部校验后才解锁“开始”。

#### A. 通用参数

| 参数 | V1 定义与校验 |
|---|---|
| 时间范围 | 起止日期；必须位于已检查时间轴中，默认完整范围。 |
| 空间范围 | `lon_min/lon_max/lat_min/lat_max`；作为**目标像元外边界**。 |
| 空间分辨率 | 正度数，纬经同分辨率；必须可整除目标范围的宽和高。 |
| 临时处理目录 | 用户可指定，推荐 SSD；系统创建任务专属子目录。 |
| 随时清理中间产物 | 默认关闭。开启后，下游阶段的完整校验通过即删除其已不再需要的上游临时 Zarr。 |
| 最终输出目录 | 必填；按现有 Zarr 非空目录与覆盖保护规则处理。 |

空间范围统一按像元外边界解释。例如 `lon=-180..180`、`lat=30..90`、0.1°，输出经纬度 shape 是 `3600 x 600`，坐标为像元中心（经度从 -179.95 起）。计划预览必须显示最终边界、中心坐标方向、shape 和逻辑体积。

V1 将全球周期经度规范化到 `[-180, 180]`。跨日界线的范围（例如 170 到 -170）明确不支持，界面应提示拆为两个任务；以后再实现周期目标范围。

计划器还必须比较目标外边界与源网格实际覆盖的像元外边界。若目标范围超出源范围，界面
在计划生成时显示“无源覆盖”的经纬度范围、对应目标格点数和预期空值比例。例如源数据
只覆盖 30--90°N、目标为 0--90°N 时，0--30°N 的目标格点不会外推，其所有时间切片
必须保持缺测。用户可以继续执行，但不能关闭这个警告或把未覆盖区域自动填为零。

#### B. Zarr 转换参数

| 参数 | 行为 |
|---|---|
| 变量 | 从已检查的数值变量中多选，至少一个。 |
| 输出变量名 | 可逐变量重命名，非空且彼此唯一。 |
| 填充值、缩放因子、输出填充值 | 复用现有 `VariableTransform` 语义，在重采样之前对源值处理。 |
| 自动调参 | 控制源文件读取/转换候选实测，默认开启。 |
| 调参预算 | 默认 60 秒。 |
| 最大并行核心 | 空或正整数；实际值仍受磁盘类型和可用内存约束。 |
| 系统预留内存 | 默认 2 GiB。 |

此面板不暴露临时 Zarr 的 chunks 或 codec。这两项由跨阶段规划器计算，避免用户分别配置转换和重采样后得到互相冲突的布局。

#### C. 重采样参数

| 参数 | V1 定义 |
|---|---|
| 方法 | `bilinear`（默认）、`conservative`、`conservative_normed`、`patch`、`nearest_s2d`、`nearest_d2s`。 |
| `skipna` | 默认开启。 |
| `na_thres` | 高级参数，默认 1.0。 |
| 计算 dtype | `source`（默认）或 `float32`，仅作用于浮点变量。 |
| 计算/空间 worker | 高级参数，默认自动。 |

用户在通用参数中给出的范围和分辨率始终定义目标网格。本面板不再提供现有重采样模块的 `source/global` 范围开关。GPP 等连续变量的默认建议为 `bilinear + skipna`。计划页要对整型变量和所选方法显示风险提示；V1 不会静默将分类变量用双线性插值。

#### D. 最终重分块与重压缩参数

| 参数 | V1 定义 |
|---|---|
| 分块策略 | `time`、`space`、`custom`；默认 `time`。 |
| 目标 chunk 大小 | 默认 128 MiB 未压缩；自动限制在 32--256 MiB 和内存安全值。 |
| 自定义 chunks | 仅 `custom` 时填写 `(time, lat, lon)`。 |
| 压缩 | `fast`、`balanced`（默认）、`maximum` 或保留现有编码。 |
| 最终 worker | 默认自动，受源/临时/输出磁盘关系约束。 |

时间连续策略固定 `time_chunk=完整选定时间轴长度`，空间块按目标未压缩大小求解。这适合按单点或小区域读取完整 8 日时间序列；若单个时间连续 chunk 过大，预览必须给出 I/O 和内存警告。

## 3. 后端阶段与跳过规则

一条龙模块应为服务层编排器，直接调用 Python 服务而不是从 GUI 通过 shell 调用多个 CLI。

~~~text
已确认 InspectionResult
        |
        v
PipelinePlanner：目标网格、转换选择、资源、布局、空间预检
        |
        +-- 网格等价 --> 转换器以最终 chunks/codec 写最终 staging --> 校验/发布
        |
        +-- 需要重采样 --> 转换器写 source-crop.zarr（临时布局/低压缩）
                                  |
                                  v
                             重采样写 resampled.zarr（临时布局/低压缩）
                                  |
                                  v
                             重分块+最终压缩写最终 staging --> 校验/发布
~~~

仅在以下条件全部成立时跳过重采样：源、目标分辨率一致；目标像元中心与源坐标对齐；目标范围能由源像元精确裁剪；且没有用户请求的其他网格变换。此时转换器直接采用最终输出的 chunks 与 codec，避免临时层和二次读写。

需要重采样时，转换阶段仅读取“源读取范围”内的源像元。源读取范围不是用户填写的
最终输出范围，而是由规划器在最终目标边界外自动扩展得到的范围；它与最终输出范围
必须在配置、日志和计划预览中分开显示。扩展量按方法增加最小但充分的 halo：

- `bilinear`、`patch`、nearest：由重采样实现的邻域规则确定；
- `conservative`、`conservative_normed`：按目标外边界和源像元边界的相交区域确定；
- 周期经度：只读取日界线另一侧实际需要的列，且不得复制 -180/180 边界。

halo 只影响临时源裁剪范围，最终输出坐标严格由目标网格定义。

### 3.1 源读取范围（裁剪范围）联合规划

用户填写的空间范围只定义最终 `TargetGrid`，**绝不能直接当作转换阶段的空间裁剪范围**。
例如用户请求 30--90°N、0.1° 输出时，若源数据为 0.05°，30°N 的目标单元可能需要
30°N 以南的源像元参与插值或面积加权。转换器若直接裁到 30°N，会使第一个输出纬向
带的数值偏差，海岸和缺测边界附近尤为明显；经度边界同理。

规划器必须在生成转换 `Selection` 前计算 `SourceReadWindow`。它以以下输入共同决定源
裁剪边界和源索引范围：

1. 用户的最终像元外边界、目标分辨率和目标坐标方向；
2. 源 `lat/lon` 的实际像元外边界、分辨率、方向、是否全球周期；
3. 重采样方法、`skipna`、`na_thres` 和目标/源分辨率比例；
4. xESMF 方法实际需要的 stencil、保守重映射的像元边界交叠，以及浮点边界容差；
5. 源可覆盖范围，避免请求范围外不存在的 I/O。

计算规则如下：

- **保守方法**：取所有与每个目标像元相交的源像元；源读取窗口至少覆盖目标外边界，
  并向每侧扩展到第一个“不再与任何目标像元相交”的源像元边界。对于非整倍数或未对齐
  的源/目标网格，该窗口不能以固定一个源格点代替。
- **双线性和 patch**：按目标边界附近所需的完整插值 stencil 扩展；先在源坐标中定位
  目标中心，再保留每个边界目标中心两侧的必要邻点。扩展层数由实现的 stencil 决定，而
  非一个写死的度数或像元数。
- **最近邻方法**：保留能成为最外层目标中心最近邻的源格点，并加入坐标比较的数值容差。
- **周期经度**：当目标边界接近 -180/180° 时，读取窗口可以拆为两个源经度切片；在临时
  Zarr 中按规范重组为连续经度序列，不能因为裁剪窗口跨日界线而遗漏另一侧的邻点。

`SourceReadWindow` 的边界一律对齐到**源像元外边界**，其包含的源索引必须完整保留到
重采样数学验证结束。计划预览至少显示“最终输出范围”“源读取范围”“每侧额外读取的
源格点数”和“因源数据不存在而无法扩展的边”，并据此估算转换逻辑字节、临时磁盘和
chunks。它同时是第 4 节 chunk 联动计算的空间输入：转换空间 chunks 围绕该源窗口和
目标 tile 对齐，而不是围绕最终范围盲目切块。

源边界不足以提供某个方法所需 halo 时，规划器不得缩小最终范围或伪造邻点。它保留可读
的源数据，标记受影响目标单元为部分/无覆盖，并让 xESMF 按 `skipna`/`na_thres` 写出
缺测或可定义的部分覆盖结果；这些单元必须进入第 6 节数学验证。

### 3.2 源覆盖范围小于目标范围

目标格网由用户参数完整创建，不能因为源范围较小而被悄悄裁短。规划器应先用源/目标
像元外边界求覆盖掩膜，并区分三类目标单元：完全覆盖、部分覆盖、完全无覆盖。

- 完全覆盖单元按用户选择的重采样方法计算；
- 部分覆盖单元交给方法和 `skipna`/`na_thres` 语义处理，并列入数学验证样本；
- 完全无覆盖单元不允许外推，必须写成该变量的缺测值。

该掩膜用于计划预览、运行日志和重采样后验证。最终 Zarr 的全局属性应记录源覆盖外边界、
目标外边界、无覆盖格点数和“未执行外推”的事实；不必为了此信息额外写入一个永久数据
变量。这样既保留用户请求的 0--90°N 目标形状，也能明确说明 0--30°N 为什么为空。

## 4. 转换 chunks 与重采样的联动

### 4.1 结论

转换输出 chunks 必须与重采样计划联动。重采样的 `time_block` 是**计算批次**，可安全跨越输入 Zarr 的 time chunk；它不能被“一个 TIFF 对应一个时间切片”的存储布局锁定为 1。执行器先物化一个有内存上限的时间批次，再调用一次向量化 xESMF。若转换器只按源文件读取效率写入，重采样会反复读取相同源块，或退化为每个时间点一次 Dask/xESMF 调度。

V1 新增 `PipelineLayoutPlan`，在写入前一次性确定：

1. `source-crop.zarr` 的每变量输入 chunks；
2. 重采样的目标空间 tile、源窗口、`time_block`、计算/空间 worker；
3. `resampled.zarr` 的中间输出 chunks；
4. 最终 `ChunkPlan` 和 `CompressionPlan`。

预览必须逐变量展示三套 chunks、单块未压缩大小和原因，不能只显示最终布局。

### 4.2 具体规划算法

1. 建立精确 `TargetGrid`，再按第 3.1 节生成 `SourceReadWindow`；得到源裁剪 shape、各变量 dtype、原生 chunks 和磁盘特征。
2. 计算最终 shape、逻辑字节数和是否网格等价。只有网格等价时，`SourceReadWindow` 才可等于最终范围。
3. 用第四面板参数计算最终 `ChunkPlan`，但需要重采样时不直接将其用作重采样输出布局。
4. 以目标分辨率比例、变量 dtype、源/目标 chunks、可用内存、方法和周期经度行为，调用重采样自动调参，联合求安全的目标空间 tile、源窗口和 `time_block`。自动时间批次当前上限为 64；这是内存保护，不是源文件 time chunk 的限制。
5. 反推 `source-crop.zarr` 布局：
   - `time_chunk` 等于 `time_block`，或为其安全整数倍；逐文件时间产品的写入任务必须独占完整 time chunk，避免并发读改写；
   - 自动模式使用约两个源空间 chunks 覆盖默认重采样 tile 的一个边，降低转换写入粒度同时保持重采样读取对齐；
   - 当源窗口跨越 chunk 边界时，以减少读取总量为目标，不只追求最大 chunk；
   - 所有变量按自己的维度顺序生成 chunks，受每 worker 未压缩内存上限限制。
6. `resampled.zarr` 默认继承上述临时 `time_chunk`，空间 chunks 与输出 tile 对齐，使任一 worker 独占完整输出 chunk；由此避免并发读改写，以及重采样器为最终大 time chunk 额外生成中转层。
7. 重分块器将该中间布局一次性变换为最终时间连续布局和用户压缩。

因此，重采样前的临时 Zarr **不应**写成完整 time-contiguous chunks。重采样需要较短 time block 控制内存；完整时间连续性只在最后一次重分块中建立。

### 4.3 所需接口扩展

- 转换器：在 `ConversionConfig` 和写入计划中增加可选的每变量 chunks/codec。未传入时保持现有自适应行为；文件名模式与完整 time 模式必须一致支持。
- 重采样器：在 `ResampleConfig` 中增加目标边界和显式中间输出 chunks，不再仅支持 `source/global` 范围和继承输入 chunks。
- 自动调参：支持以“目标网格 + 源裁剪窗口 + 临时布局”为输入，输出可解释的 `PipelineLayoutPlan`。
- 重分块器：复用当前两阶段流式实现，只负责中间 Zarr 到最终 Zarr 的一次布局/codec 转换。

## 5. 临时数据、编码和磁盘安全

### 5.1 临时目录

每个任务都在用户指定临时根下创建唯一目录：

~~~text
<temporary-root>/fast-nc-zarr-pipeline/<job-id>/
  manifest.json
  source-crop.zarr/       # 仅需要重采样时创建
  resampled.zarr/         # 仅需要重采样时创建
  weights/                 # xESMF 权重和任务日志
~~~

`manifest.json` 保存任务 ID、创建时间、输入/输出绝对路径和所有权标识。清理只允许删除带有效 manifest 且任务 ID 匹配的目录，绝不能清空用户指定的临时根。成功后删除任务目录；失败或取消后保留，并在报告中返回路径。

最终输出先写到 `<output-parent>/.<name>.pipeline-<job-id>.tmp`，最终校验成功后才原子发布。已有非空目录依旧只允许覆盖可确认的 Zarr store。

#### 随时清理中间产物

通用参数的“随时清理中间产物”默认关闭，关闭时保留所有成功阶段的临时层到整条任务
成功，便于排查。用户开启后采用严格的“**先验证，后删除**”策略：

1. `source-crop.zarr` 只能在 `resampled.zarr` 的结构、坐标、覆盖掩膜和数学验证全部
   通过后删除；
2. `resampled.zarr` 只能在最终 Zarr 已完成重分块/压缩、最终校验通过且已成功发布后删除；
3. 任务取消、异常或任一验证失败时，当前仍存在的临时层必须保留，不能因节省空间而
   删除唯一的排查证据；
4. 每次删除前后都更新 `manifest.json` 和任务日志，记录已释放的字节数、路径及下游
   验证报告摘要。

因此该选项会降低成功任务的峰值临时空间，但会牺牲从已删除阶段直接重跑的能力。它尤其
适合数据量远大于临时盘容量、且用户接受“发生后续错误时从源数据重新执行”的场景。

### 5.2 临时编码

所有一条龙过程产生的临时 Zarr 固定使用低成本编码：

- Zarr v3 `BloscCodec(cname="zstd", clevel=1)`；
- 浮点变量使用 `shuffle`，整数变量使用 `bitshuffle`，坐标使用轻量编码；
- 不使用用户选择的高等级最终压缩；
- 不主动使用 sharding；仅保留现有重分块器在百万级逻辑 chunks 时的保护行为。

最终输出才应用第四面板指定的 `fast`、`balanced` 或 `maximum` 编码。这样避免反复进行昂贵的最终压缩，同时不让临时层完全无压缩而占满磁盘。

### 5.3 磁盘预检

规划器按采样压缩率和 25% 波动余量分别估计源裁剪层、重采样层、最终 staging、权重和元数据空间。临时盘和最终输出盘可能不同，必须分别检查。

开启“随时清理”时，重采样任务的峰值至少取下列两项较大者：

~~~text
source-crop + resampled-staging
resampled + final-staging
~~~

关闭该选项时，成功的上游层会保留到最后，预检必须按更保守的 `source-crop + resampled + final-staging` 估计峰值（并加权重和元数据空间）。计划预览应同时显示两种模式的峰值，使用户能以可见的空间代价决定是否开启清理。

空间不足时不创建任何输出，并显示各层估算、可用空间和建议（缩小范围、使用 SSD 临时目录、降低并行、调整最终 chunk 目标）。

## 6. 重采样数学验证

### 6.1 执行时机与目标

每次重采样成功写出 `resampled.zarr` 后，必须在删除 `source-crop.zarr` 之前执行数学
验证。这不是为了重新实现或质疑 xESMF/ESMF 的 conservative、bilinear 等数学算子；
V1 的重采样数学以已安装版本的 xESMF 为唯一权威实现。

验证的目标是确认一条龙编排没有改变 xESMF 应得到的结果：`SourceReadWindow` 是否保留
了完整边界 stencil、变量变换是否一致、`skipna`/`na_thres` 是否传递正确，以及分块、
并发和 Zarr 写入是否造成了数值或缺测变化。

参考路径使用已通过转换校验的 `source-crop.zarr`，即生产重采样器的精确输入（已包含用户
指定的变量重命名、填充值和缩放因子）。验证器不得复用生产用的流式 tile 写入循环；它对每个
样本中心及其相邻的最多 3×3 个目标单元，按生产引擎相同的局部源窗口、周期经度规则、方法、
`skipna` 和 `na_thres` 新建小型 `xesmf.Regridder`，再直接计算参考值。这样既避免重复打开
原始多文件集合和重复实现变量变换，也不会为单个样本构造全局源网格权重；转换裁剪的 halo
正确性则由规划器的源窗口规则、转换阶段边界校验和针对该规则的回归测试共同保证。

任务报告必须记录 xESMF/ESMF 版本、方法、`skipna`、`na_thres`、源/目标网格哈希和参考
窗口边界，并链接至 [xESMF User API](https://xesmf.readthedocs.io/en/stable/user_api.html)。

### 6.2 分层样本选择

规划器从所有空间变量共享确定有限、可复现的样本，默认最多 6 个局部空间窗口，并从
时间范围的开头、中间和结尾各取一个有效时间切片。样本必须分层覆盖：

- 至少一个内部的完全覆盖格点；
- 北、南、西、东四条目标边界附近的格点；
- 有效源值与缺测值相邻的格点（典型为海岸线）；
- 部分源覆盖格点；
- 完全无源覆盖格点（若目标范围超出源范围）。

样本在边缘、中心和内部位置确定性选择，保证同一任务可复验；单个窗口的权重只构建一次，
随后复用于该窗口的所有变量和时间点。没有满足某一类别的格点时，报告该类别不存在而不是
伪造样本。完整样本清单、源/目标索引和误差写入任务报告，不写入最终数据变量。

### 6.3 xESMF 的缺测与方法语义

验证器必须直接使用用户所选方法，不为 `conservative + skipna`、bilinear 或其他方法
另写近似数学公式。根据 xESMF User API，`skipna=False` 时一个缺测输入可使输出掩膜；
`skipna=True` 时只使用有效输入，只有参与计算的缺测比例超过 `na_thres` 才输出 `NaN`，
否则由 xESMF 进行重归一化。`na_thres` 的默认值为 1.0。详细行为以
[Masking and extrapolation](https://xesmf.readthedocs.io/en/stable/notebooks/Masking.html)
和任务实际锁定的 xESMF/ESMF 版本为准。

因此，用户举例的“0.05° 到 0.1°、conservative、开启 skipna、边界或海岸附近有缺测”
将作为一个重点样本类别：参考路径调用相同 xESMF 参数，生产输出必须与其匹配。验证报告
展示实际参与的源/目标索引、`NaN` 判定、参考值、生产值和误差，但不自行声明面积权重或
有效分母的实现细节。

所有 xESMF 方法均采用这条参考路径。`patch` 不再被降级为特殊的自定义矩阵验证；其结果
同样由安装版本 xESMF 的小窗口参考重算作为判据。

### 6.4 判定和覆盖验证

每个比较以 dtype 和数值尺度导出的 `rtol`/`atol` 判定；默认对 float32 使用不小于
`5e-5` 的相对容差，对 float64 使用不小于 `1e-10`，同时记录绝对误差。输入/输出均为
缺测才通过；一方缺测、另一方有效即失败。整数变量的 nearest 验证要求精确相等。

对完全无源覆盖的目标掩膜，验证器必须抽样并全量检查输出为缺测，确保不存在由初始化、
编码或重采样器默认值产生的零值；参考路径同样必须得到缺测。部分覆盖格点必须同时进入
数学抽样。任何数学、坐标、覆盖或容差验证失败都应阻止发布最终输出，并且即使开启“随时
清理”也不得删除上游中间层。

## 7. 校验、取消和结果报告

- 转换阶段复用现有时间、坐标、变量和源值抽样校验；
- 重采样阶段校验目标边界、坐标、shape、变量维度、dtype、布局、无覆盖掩膜和数学样本；
- 重采样主体完成后，`manifest.json` 先切换为 `validating_math_samples`，日志输出局部数学
  验证的窗口/变量/时间点总数及进度；验证期间可响应取消，避免界面看似停滞；
- 最终阶段复用重分块的 codec/chunk/属性/坐标/抽样值校验；
- 最终报告记录检查快照、四面板配置、派生计划、每阶段耗时、吞吐、空间使用、最终 shape/chunks/codecs 和输出路径。

取消信号在阶段边界和每个 I/O 块后检查。取消或异常时不得发布最终路径，也不能将临时目录报告为成功结果。GUI 任务页复用现有 CPU、RSS、吞吐和日志展示，并额外显示当前阶段以及仍保留的任务目录。

## 8. 代码结构与 API

~~~text
src/fast_nc_zarr/
  pipeline/
    __init__.py
    models.py       # PipelineConfig、PipelinePlan、PipelineLayoutPlan、报告模型
    validation.py   # 四面板参数、网格边界、路径、磁盘校验
    planner.py      # 跳过判断、目标格网、跨阶段布局、空间估算
    engine.py       # 编排、取消、临时生命周期、最终发布
    cli.py          # fast-zarr-pipeline
  application/services.py  # preview_pipeline / run_pipeline
  gui/                      # “一条龙处理”页及后台 worker
~~~

建议使用以下不可变对象边界：

~~~python
@dataclass(frozen=True)
class PipelineConfig:
    general: PipelineGeneralConfig
    conversion: ConversionConfig
    resampling: PipelineResamplingConfig
    finalization: PipelineFinalizationConfig

@dataclass(frozen=True)
class PipelinePlan:
    inspection_id: str
    target_grid: TargetGrid
    source_read_window: SourceReadWindow
    needs_resample: bool
    conversion_layout: WriteLayout
    resample_layout: ResampleLayout
    final_plan: ChunkPlan
    final_compression: CompressionPlan
    temporary_paths: TemporaryPaths
    disk_estimate: DiskEstimate
~~~

`PipelineConfig` 只保存用户意图；`PipelinePlan` 保存所有验证过的派生值。执行器只接收计划，不能在写入中重新推断时间规则、目标网格或 chunks。

## 9. 开发顺序与验收

实施顺序：

1. 新增目标边界网格构造、四面板配置模型和纯规划器；以 30--90°N、-180--180°、0.1° 验证 3600 x 600 目标网格。
2. 扩展转换器的显式写入布局/临时 codec，以及重采样器的目标边界/显式中间 chunks。
3. 实现无 GUI 的 `preview_pipeline` 与 `run_pipeline`，并先提供 CLI/API。
4. 实现 GUI 一条龙页面：绑定已确认检查结果、四面板、计划预览、开始/取消。
5. 补齐运行报告、快照、磁盘预检和失败恢复。

自动化验收至少覆盖：

- TIFF/NetCDF 的 DOY 时间确认后才可启动；
- 目标边界、0.1° 坐标和时间裁剪严格正确；
- 目标 30--90°N、源 0.05°、目标 0.1°时，转换源窗口必须按方法保留 30°N 以南所需 halo，且最终输出仍严格从 30°N 开始；经度边界和周期经度同样覆盖；
- 网格等价时跳过临时层并直接输出最终 codec/chunks；
- 需要重采样时，转换 chunks 与 `time_block`、空间 tile 联动；
- 临时层恒为 Zstd level 1，最终层严格匹配用户压缩方案；
- 缺口拒绝和显式补齐、空间不足、已有输出保护、取消、异常后保留任务目录；
- 最终变量变换、时间轴、shape、chunks、codec 和代表性数值全部正确。

## 10. 还应纳入 V1 的优化与保护

以下项目不改变四面板的主流程，但能显著降低大数据任务的时间、空间或误用风险，应作为
V1 的明确实现要求。

1. **计划先行和 dry-run**：计划页显示阶段是否跳过、源裁剪/目标 shape、三套 chunks、
   每阶段预计读写量、两种清理模式峰值空间和 worker 分配；CLI 支持只生成计划而不写入。
2. **并发总量约束**：空间进程数乘每进程计算线程数不得超过用户最大核心数；同一机械盘
   上的源、临时和输出发生重叠时自动降低并发，避免随机 I/O 寻道放大。
   ESMF 每个空间进程的常驻内存按至少 1.5 GiB 预留；空间块完成日志必须分别给出权重构建、
   源窗口读取、重采样和写入耗时，便于依据真实瓶颈调整 tile、时间批次和并发数。
3. **权重可追溯且可复用**：xESMF 权重文件以源/目标坐标边界、方法、周期性、ESMF 版本的
   哈希命名。V1 至少在同一任务内复用；后续跨任务缓存只能在哈希和版本完全匹配时使用，
   否则必须重新生成。
4. **参数和来源写入结果**：最终 Zarr 全局属性和独立 JSON 报告记录源检查快照哈希、
   时间规则、目标网格、方法、skipna、覆盖警告、最终 chunks/codec 和软件版本，保证结果
   可追溯、可复现。
5. **取消后的可恢复性**：`manifest.json` 记录各阶段的输入哈希、完成状态和验证摘要。
   未开启滚动清理时，未来可安全实现从已验证阶段继续；开启清理时明确只能从仍存在的最近
   阶段继续或从源重跑，不能错误地声称可恢复。
6. **不在计划中隐藏降级**：目标范围不整除、网格未对齐、内存不足、无法数学验证的模式，
   都必须给出可操作错误或显式风险确认；不能静默改变分辨率、范围、方法或缺测规则。

## 11. V1 默认值

| 项目 | 默认值 |
|---|---|
| 时间/空间范围 | 已检查的完整范围，用户可缩小 |
| 目标网格 | 用户范围为像元外边界；纬度方向保持源方向 |
| 重采样 | `bilinear`、`skipna=True`、`na_thres=1.0` |
| 中间 codec | Blosc Zstd level 1；浮点 shuffle、整数 bitshuffle |
| 转换自动调参 | 开启，60 秒预算 |
| 最终 chunks | `time` 策略，128 MiB 未压缩目标 |
| 最终压缩 | `balanced` |
| 时间缺口 | 默认阻止，用户显式确认才补齐 |
| 随时清理中间产物 | 默认关闭；开启后只在下游验证成功后删除上游层 |
| 重采样数学验证 | 默认且必须执行；在删除 `source-crop.zarr` 前完成 |
| 临时目录 | 用户指定优先；未指定时在输出同文件系统创建受控目录并提示性能风险 |
