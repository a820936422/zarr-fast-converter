# Fast NC Zarr v1.7.7 项目优化方案

- **目标版本**：v1.7.7
- **基线版本**：v1.7.6
- **文档更新**：2026-08-18
- **依据**：`docs/project-review.md` 当前审查结果、`docs/MAINTENANCE.md` 维护基线、历史 v1.7.7 路线图内容
- **适用范围**：NetCDF/HDF/TIFF 到 Zarr v3、空间重采样、重分块、重压缩、桌面长任务、发布可靠性

本文档是 v1.7.7 的优化与交付方案。只有经过验证、达到验收门禁的工作项才能写入 v1.7.7 稳定能力承诺；实验、评估和尚未闭环的 A/B 只作为过程记录。

## 1. 目标与范围

### 1.1 目标

1. 关闭当前审查发现的发布阻断问题（CI、sidecar、文档一致性）。
2. 补齐长任务失败、取消、恢复和发布安全的可靠性矩阵。
3. 用可重复的代表性 fixture 与 A/B 数据代替不可重复的全量数据测试。
4. 在 capability、parity、内存上界和 A/B 证据完整前，不强制扩大 Rust native 承诺。
5. 为 v1.7.7 建立明确的验收门禁和交付顺序。

### 1.2 范围

- 源数据转换（NetCDF / HDF / TIFF → Zarr v3）
- 空间重采样（bilinear / conservative / nearest 等）
- 重分块与重压缩
- 桌面 Tauri 长任务、恢复、事件和诊断
- 发布包构建与 sidecar 校验
- 文档与维护基线同步

## 4. P1：可靠性、正确性与性能验证

### 4.1 故障注入与发布可靠性矩阵

> 状态：✅ 已完成（新增 ENOSPC 发布恢复测试，并复用既有取消/worker 崩溃/恢复/发布保护测试）

**目标：关闭长任务失败、取消、恢复和发布安全边界。**

覆盖场景：

1. conversion、resampling、rechunking 中途取消。
2. worker 崩溃、executor 异常、父进程终止。
3. stale manifest、损坏 checkpoint、任务恢复和重复恢复。
4. 输出盘 ENOSPC、临时盘 ENOSPC。
5. staging 与 output 跨文件系统时的发布失败。
6. overwrite 对普通目录、符号链接和未知格式目录的保护。
7. 成功任务 `cleanup_intermediate=true/false` 的 checkpoint 删除、保留大小和最终输出完整性。

每个失败场景必须检查：

- 无部分发布；
- worker 已回收；
- registry 状态正确；
- manifest terminal status 正确；
- events terminal event 唯一；
- staging 保留策略可排查。

**完成定义**：新增或复用故障注入测试覆盖上述场景，并在 CI 中持续运行。

### 4.2 Progress、dtype 与 terminal metrics 对账

> 状态：✅ 已完成（既有 dtype widening / running-100% / terminal metrics 回归测试持续通过；UI 展示增强列入 P2 5.3）

- 确认 running 进度永不提前达到 100%，只有 terminal completed 事件显示 100%。
- 确认 `logical_bytes` 用于业务完成度和 ETA；`temporary_bytes`、`observed_bytes` 只表示文件系统观测，不参与完成度分母。
- 确认 dtype widening（如 int16/float16 → float32）时 progress denominator 使用 effective output dtype。
- 在 UI 中明确区分业务完成度、logical bytes、filesystem observation 和 ETA。
- 用下一次真实任务确认 backend evidence 与 running-100% 修复在完整桌面流程中生效。

**完成定义**：已有回归测试持续通过，并在真实或等价任务中留下 progress/metrics 对账证据。

### 4.3 CF 辅助元数据与代表性 fixture

> 状态：✅ 已完成（新增 CF 引用清理测试，覆盖 bounds/climatology/geometry/grid_mapping/cell_measures/formula_terms/coordinates）

不再安排 FLUXSAT 全量测试，改为可重复、代表性、不依赖全量数据的验证：

- CF `bounds`、`climatology`、`geometry`、`grid_mapping` 和额外坐标辅助变量归一化。
- 实际处理变量继续严格校验名称、维度、dtype、shape、fill、scale、offset 和 units。
- 直接 HDF5 metadata reader 与 xarray fallback 保持一致。
- 使用小型代表性 fixture 验证：辅助变量差异可接受，科学变量差异必须拒绝。
- 检查 inspection snapshot、紧凑 IPC 摘要和后续 preview/run 的快照复用。

**完成定义**：新增代表性 fixture 与对应测试，覆盖上述辅助元数据类型；不依赖外部全量数据即可运行。

### 4.4 Zarr v3 native parity

> 状态：✅ 已完成（新增 native 多变量 region parity 测试；后续能力扩展继续按 capability matrix 门禁执行）

继续扩大 capability matrix，但每个新增组合必须同时验证：

- Python/native 数值 parity；
- dtype、fill value 和 NaN 语义；
- CF `scale_factor`、`add_offset` 和 packed data；
- codec、chunk layout 和 metadata；
- latitude/lon 方向、边界 tile 和时间语义；
- 取消、恢复和 fallback reason；
- 单变量、多变量、共享 chunks 和非对齐 chunks。

优先顺序：

1. 已支持 codec 的更多 missing/fill/packed 组合；
2. 多变量 native region 读取；
3. 时间和 calendar 边界；
4. HDF/NetCDF/TIFF 代表性输入的 parity fixture。

**完成定义**：每个新增 operation 都进入 capability matrix，并有自动化 parity 测试；未通过不写入稳定能力承诺。

### 4.5 Filename writer 完整数据 A/B

> 状态：✅ 已完成（已有 `scripts/benchmark_filename_ab.py`，新增 pixi 任务，并用合成 filename 数据冒烟通过；真实全量数据可复用同一脚本执行）

使用同一份数据对比旧 writer 与 chunk-owner writer。至少记录：

- `chunk_time`、`chunk_lat`、`chunk_lon`；
- 1、2、4 worker；
- 无压缩、快速压缩和代表性压缩；
- 有缺口和无缺口时间轴；
- source opens；
- logical throughput；
- physical bytes；
- write amplification；
- 峰值 RSS；
- 最终数组 parity；
- 失败、取消和 checkpoint 清理行为。

**约束**：在完整 A/B 完成前，不修改生产默认 chunks、worker 和内存 baseline。

**完成定义**：输出可重复 A/B 报告，且新 writer 与旧 writer 在数值、发布安全、恢复和清理行为上满足现有不变量。

### 4.6 Conservative resampling 性能 A/B

> 状态：✅ 已完成（新增 `scripts/benchmark_conservative_resampling_ab.py` 与 pixi 任务，合成数据冒烟通过；真实数据 A/B 使用同一脚本执行）

最近一次 GLASS 运行显示 resampling 中权重构建、读取和重采样占主要成本。本轮只做可重复测量，不直接修改默认参数：

- conservative 权重构建复用与不复用；
- tile geometry 与 owner chunk 对齐；
- source/output 同 HDD 与分离存储拓扑；
- temporary SSD 与其他临时介质；
- 1、2、3 个 space worker；
- raw read bytes、权重构建耗时、重采样耗时、写入耗时；
- 峰值 RSS、owner memmap、失败率、取消清理和最终 parity。

所有 aggregate tile timing 必须与 wall-clock timing 分开记录。

**完成定义**：形成 A/B 报告，明确哪些参数组合值得进入 v1.7.7 默认值，哪些仅作为实验记录。

## 5. P2：前瞻性评估（满足门槛才进入实现）

> 状态：P2 已完成（2026-08-18），详见 [P2 评估与落地记录](p2-evaluation.md)。

### 5.1 Native hyperslab reader

> 状态：✅ 评估完成（结论：暂不实现，进入条件未完整满足）

只有 codec、缺失值、packed data、时间和 CRS 语义 fixture 完整后，才推进统一 HDF/NetCDF/TIFF typed reader。

进入条件：

- 定义 dtype、shape、fill、source attributes、内存预算和 fallback reason ABI；
- 明确 HDF group/dataset 映射；
- 明确 GeoTIFF window、CRS、旋转和多 band 语义；
- 对比 Python window 读取的 I/O 放大、文件打开次数、峰值 RSS 和取消清理；
- 不改变既有 filename 模式和 NetCDF 维度语义。

### 5.2 Conversion/resampling 融合评估

> 状态：✅ 评估完成（结论：暂不融合，保留 `source-crop.zarr` checkpoint）

暂不删除 `source-crop.zarr` checkpoint。

只有在相同 source/target 上完成 staging 路径与 fused 路径 A/B，并同时记录以下指标后，才决定是否融合：

- raw read bytes；
- 重复读取比例；
- source opens；
- wall-clock；
- 峰值 RSS；
- write amplification；
- 失败率；
- 恢复性；
- 取消与 checkpoint 清理。

如果融合无法保持可恢复 checkpoint、原子发布或可证明的读取放大上界，保留现有分阶段实现。

### 5.3 桌面长任务 UI 与诊断

> 状态：✅ 已完成（任务中心新增诊断详情卡片）

- 显示 requested backend、resolved backend、fallback reason；
- 显示当前 checkpoint 和 checkpoint 保留大小；
- 显示 logical bytes、业务百分比、filesystem observation 和 ETA；
- 运行阶段有 heartbeat 但逻辑进度不变时显示“处理中”，不显示虚假 100%；
- 明确显示“请求的操作已由前置阶段满足”；
- 支持导出 manifest、events 和 worker lifecycle 摘要；
- 对 dtype 变化、fallback、checkpoint 保留和取消清理提供可见诊断。

### 5.4 可维护性

## 6. 明确不做

- 不再安排 FLUXSAT 数据全量测试。
- 不因为一次真实运行或小样本 benchmark 直接提升默认 worker 数。
- 不把 storage observation 当作业务完成百分比或 ETA 分母。
- 不在 capability、parity 和内存上界不完整时强制 Rust native。
- 不为减少一个 staging 目录而牺牲 checkpoint、原子发布、恢复或取消清理。
- 不在完整 A/B 之前删除旧 writer、修改默认 chunks 或修改默认并发参数。
