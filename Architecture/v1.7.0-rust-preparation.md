## 3. 环境补齐计划

### 3.1 Pixi 工具链

由于项目当前以 Pixi 作为唯一环境来源，优先将以下工具加入 `pixi.toml`，而不是要求每个开发者单独安装不同版本：

```text
rust             >= 1.83
maturin          >= 1.8,<2
pip              >= 26.2.1,<27
pkg-config
cmake
ninja
```

Rust 版本需要满足当前 PyO3 的最低要求。Cargo workspace 还应在 `Cargo.toml` 中设置 `rust-version = "1.83"`，并提交 `Cargo.lock`。

如果 conda-forge 的 Rust 包不能提供 clippy/rustfmt，再在开发机或 CI 中补充对应组件；不得让生产构建依赖开发者个人 Rust toolchain 路径。

### 3.2 Python bridge

需要验证：

- Pixi Python 3.13 的 include 目录可被 PyO3/maturin 找到；
- `numpy` 的 C API 或 buffer protocol 可用；
- maturin 能构建 `fast_nc_zarr._native`；
- `maturin develop --release` 后 Python 可以导入扩展；
- 扩展导入失败时 Python backend 仍能工作。

建议初期使用 PyO3 `extension-module`，不在 Rust 中嵌入 Python 解释器。

### 3.3 C/C++ 和 Rust 构建工具

至少需要：

- C/C++ 编译器；
- linker；
- CMake；
- Ninja 或 Make；
- pkg-config；
- `patchelf` 或等效 wheel 修复工具；
- Python development headers；
- zlib、zstd、Blosc 等 codec 库。

当前 GCC 和 CMake 已存在，Ninja、Rust、maturin 尚未存在，需要补齐并锁定版本。

### 3.4 数据格式 native 库

#### 第一阶段必需

- `zarrs`：纯 Rust Zarr v3 实现；
- `ndarray`：受控数值 buffer；
- `rayon` 或自定义受控线程池；
- `serde`、`serde_json`、`thiserror`。

这些依赖不要求 ESMF 或 HDF5 FFI，可以先完成 Zarr 重分块原型。

#### 第二阶段验证

- NetCDF C headers/shared libraries；
- HDF5 headers/shared libraries；
- GDAL headers/shared libraries；
- 对应的 `pkg-config`、`nc-config`、`gdal-config` 发现路径。

当前 `gdal-config` 和 `nc-config` 可用，但 HDF5 的 `h5cc` 与 `.pc` 配置尚未验证。不能在环境发现逻辑未解决前启用 `hdf5-metno`。

#### 暂不加入

- ESMF Fortran 编译链；
- ESMF Rust FFI；
- Qt Rust bindings。

v1.7.0 继续由 Python xESMF 和 PySide6 提供这两部分能力。

## 4. 构建和打包准备

### 4.1 Cargo workspace

根 `Cargo.toml` 至少应包含：

```toml
[workspace]
resolver = "2"
members = ["rust/crates/*"]

[workspace.package]
edition = "2021"
rust-version = "1.83"
```

公共依赖版本放在 `[workspace.dependencies]`，避免各 crate 使用不一致版本。

### 4.2 pyproject 与 maturin

根目录增加 `pyproject.toml`，负责：

- 构建 backend；
- Python 包元数据；
- maturin manifest path；
- `fast_nc_zarr._native` module name；
- Python source root `src`；
- 后续 wheel 构建。

第一次只要求 `maturin develop`，不立即发布 PyPI wheel。

### 4.3 构建任务

建议新增 Pixi task：

```text
native-check
native-develop
native-build
rust-test
rust-fmt-check
rust-clippy
cross-backend-test
```

现有 `pixi run test` 必须继续保留，并继续使用 Qt offscreen 配置。

- 不先移动全部 Python 模块；
- 不先删除 Dask 或 xarray；
- 不先安装 ESMF Rust FFI；
- 不先迁移 PySide6 GUI；
- 不先改变 manifest schema；
- 不先将 Rust backend 设为默认；
- 不先用大规模真实数据做没有 golden output 的 benchmark；
- 不把系统全局 Rust、Pixi Rust 和 rustup Rust 混用而不记录来源。

## 7. 第一个实施任务的完成标准

第一批代码开始前，必须能执行：

```bash
pixi run native-check
pixi run native-develop
pixi run rust-test
pixi run cross-backend-test
pixi run test
```

并得到：

1. Python 3.13 环境中 `_native` 可导入；
2. Rust crate、Python extension 和 Python package 版本协议一致；
3. Python/Rust 最小 Zarr v3 fixture 交叉读写通过；
4. 既有 1.6.9 测试全部通过；
5. native backend 失败时 Python backend 可解释地接管；
6. 当前 `main` 不受任何影响。
